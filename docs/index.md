## Типы документов и достоверность

| Метка | Значение |
|---|---|
| observed_snapshot | Описание структуры/поведения по обследованию 2026-09-07; не текущие финансовые данные |
| proposed_workflow | Рекомендуемые действия агента или пользователя; не готовый программный адаптер |
| planned | Требования к будущему выпуску; выполнение ещё не подтверждено |
| navigation | Индекс для поиска; не самостоятельный контракт |
| mixed | Содержит несколько типов сведений с явными пояснениями внутри |

Текущие денежные факты берутся из авторизованного вызова своей базы. Значения в примерах — синтетические. Срез схемы, версия JSON-статуса и версия формата манифеста — три разные версии.

## Точные справочники

- [Схема Markdown](schema.md) — типы, связи, ограничения, триггеры.
- [Схема JSON](reference/schema.json) — те же объекты, удобные для фильтрации программой.
- [Функции Markdown](functions.md) — сигнатуры, комментарии и ссылки на отдельные перегрузки.
- [Функции JSON](reference/functions.json) — уникальный signature_id, типы, необязательные параметры и ссылка на нужную секцию.

JSON-каталоги не являются OpenAPI, MCP-описанием инструментов или установочным SQL. Отсутствие тела функции в каталоге не позволяет восстановить её алгоритм по одному названию.

## Как читать агенту

1. Определить intent.
2. Найти его в таблице или массиве tasks манифеста.
3. Загрузить только указанные документы/разделы.
4. При обращении к функции выбрать точную перегрузку из каталога; не угадывать аргументы.
5. До работы с живой базой проверить соответствие её контракта описанному срезу.
6. Использовать предусмотренный маршрут и проверять фактический результат.

[Манифест](manifest.json) содержит пути от корня репозитория. Обычные Markdown-ссылки разрешаются относительно текущего файла.
