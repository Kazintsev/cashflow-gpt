## Что можно написать в чат

Фразы ниже — примеры диалога, а не гарантированный синтаксис существующего парсера. Их интерпретацию обеспечивает ассистент, работающий по инструкциям проекта.

| Намерение | Пример | Что должно произойти |
|---|---|---|
| Расход | «Запиши 450 ₽, обед, с основной карты» | Расход с указанного счёта, обычно в бюджете на жизнь |
| Наличные | «700 ₽ продукты, наличными» | Расход с наличного счёта |
| Вне бюджета | «3 000 ₽ инструмент, с основной карты, вне бюджета» | Реальные деньги уменьшаются; бюджет недели не расходуется |
| Доход | «Получил 60 000 ₽ на основную карту» | Увеличивается баланс счёта; при необходимости уточняется вид дохода |
| Перевод | «Снял 5 000 ₽ с основной карты в наличные» | Одна операция между двумя счетами |
| Обеспечение | «Перевёл 8 000 ₽ на счёт предстоящего платежа» | При корректной связи платёж становится обеспеченным |
| Исполнение | «Банк списал платёж по кредиту» | Подтверждается фактическое списание и его состав |
| Исправление | «Операция №123 была оплачена наличными» | Изменяется существующая операция, не создаётся второй расход |
| Статус | «Статус» | Единый отчёт до ближайшего дохода |
| Платежи | «Платежи на ближайшие 10 дней» | Список с обеспеченностью и явно указанными границами |
| Полный календарь | «Все платежи до указанной даты, включая исполненные» | Отчёт с отдельным фильтром, сохраняющим исполненные события |
| Категории | «На что ушёл бюджет этой недели?» | Расходы `life` по категориям, включая разбиения чеков |

## Какие сведения нужны для записи

У каждой операции должны быть понятны сумма, дата/время и направление денег. Для расхода нужен счёт списания; для дохода — счёт зачисления; для перевода — оба счёта. Для кредитного платежа может понадобиться конкретный долг, событие календаря и разбивка на тело, проценты и комиссию.

Счёт по умолчанию можно использовать только после явной настройки. Новую категорию следует согласовать. Неясную формулировку «оплатил кредит» нужно уточнить: это перевод денег на платёжный счёт или уже списание банком?

## Бюджет и категория — независимые признаки

Категория отвечает на вопрос «на что потрачено», а `budget_effect` — «как операция влияет на бюджет»:

| Значение | Значение для пользователя |
|---|---|
| `life` | Расход учитывается в недельном бюджете |
| `excluded` | Расход вне недельного бюджета |
| `none` | Операция не является расходом бюджета, например перевод |

Одинаковая категория может встречаться и внутри, и вне бюджета. Наличие категории «Лекарства» само по себе не определяет бюджетный признак.

## Как читать статус

| Блок | Смысл |
|---|---|
| Деньги в наличии | Остатки активных банковских и наличных счетов |
| Свободные деньги | Средства после необходимых резервов до следующего дохода |
| Бюджет недели | Лимит, фактические траты, остаток или перерасход |
| Сегодня | Неисполненные расходные события текущей бизнес-даты |
| Контроль | Прошедшие события, для которых исполнение не подтверждено |
| До следующего поступления | Неисполненные события после сегодня и строго до даты дохода |
| Проверка данных | Найденные ошибки и предупреждения согласованности |

Учебный фрагмент: «Деньги в наличии — 50 000 ₽; свободно до следующего дохода — 18 000 ₽; бюджет недели — 7 000 / 10 000 ₽». Это три разных показателя; объяснение формулы — в [правилах расчётов](calculations.md).

Если ближайшее поступление не задано, вместо свободной суммы до дохода должно быть «нет даты следующего поступления». Нельзя заменять неизвестное значение нулём.

## Кредитные карты

Покупка по кредитке расходует недельный бюджет в момент покупки. Погашение карты не расходует этот бюджет второй раз. Непогашенные бюджетные покупки могут создавать резерв собственных денег.

Полностью погашенные бюджетные расходы по карте не нужно показывать отдельной строкой долга в кратком статусе. История расходов при этом сохраняется.

## Обеспечен и исполнен

- **Обеспечен:** деньги уже перемещены из обычного cash на платёжный буфер и связаны с событием.
- **Исполнен:** подтверждена операция оплаты, связанная с событием.
- **Частично обеспечен / исполнен:** соответствующая сумма меньше суммы обязательства.
- **Отменён:** событие больше не должно исполняться.

Прошедший обеспеченный платёж может требовать подтверждения списания. Одна календарная дата не доказывает исполнение.

## Исправления и чеки

Для исправления сначала найдите конкретную операцию по ID, дате, сумме и описанию. При нескольких совпадениях уточните выбор. При изменении суммы проверьте связанные категории, чек, обеспечение и состав платежа.

Один чек может распределять расход по нескольким категориям. Если разбиение существует, его сумма должна совпадать с суммой расхода; нельзя суммировать и весь расход, и его строки категорий.

Таблицы хранят реквизиты и позиции чека. Автоматическое распознавание фото и проверка во внешнем сервисе требуют отдельной интеграции.
