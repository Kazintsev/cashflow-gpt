# Подготовка открытого выпуска и участие в разработке

## Что уже готово

Подготовлен пакет документации: пользовательский маршрут, правила расчётов, описание архитектуры, ключевой API с SQL-примерами, справочники схемы и функций, инструкции ассистента и матрица проверок.

Документы основаны на обследовании текущей реализации. Они не заменяют исходники, миграции и тестируемый установщик.

## Что необходимо до первой публикации

| Работа | Критерий завершения |
|---|---|
| Выгрузить структуру и код | В репозитории воспроизводимые миграции без строк личных данных |
| Убрать персональные зависимости | Настройки обязательны или имеют нейтральные значения; нет имён банков/счетов владельца и персональных числовых допущений в логике |
| Настроить доступ новой установки | Проверены разрешённые и запрещённые действия реального клиента |
| Создать демонстрационные данные | Вымышленные счета, доход, расход, карта, кредит с графиком и обеспеченный платёж |
| Упаковать интеграцию | Описан и проверен один конкретный способ подключения ассистента |
| Проверить чистую установку | Человек выполняет README в пустом окружении и получает ожидаемый статус |
| Проверить денежные сценарии | Пройдены существенные сценарии из матрицы, результаты сохранены |
| Выбрать лицензию | Добавлен LICENSE с согласованной лицензией и проверены сторонние компоненты |
| Указать репозиторий и выпуск | Все ссылки и команды содержат действительные имя репозитория и версию |

В текущих функциях обнаружены индивидуальные fallback-значения для зарплаты и начала учёта, а также форматирование отдельных названий счетов. В публичной версии их нужно заменить настройками или нейтральным поведением; документация не выдаёт эти изменения за уже выполненные.

Открытая лицензия задаёт права использования, изменения и распространения. Публичная видимость репозитория сама по себе не заменяет её. [Лицензирование репозитория на GitHub](https://docs.github.com/articles/licensing-a-repository)

## Предлагаемая структура репозитория

| Путь | Содержание |
|---|---|
| README.md | Назначение, возможности, проверенный быстрый запуск |
| LICENSE | Выбранная лицензия |
| docs/ | Эти руководства и справочники |
| supabase/migrations/ | Версионируемые изменения схемы и функций |
| supabase/seed.sql | Только вымышленные демонстрационные данные |
| tests/ | Регрессия денежных сценариев и доступа |
| integration/ | Конфигурация/код выбранного клиентского адаптера |
| .env.example | Имена необходимых параметров без действующих секретов |
| CHANGELOG.md | Изменения поведения и совместимости |

Это целевая структура. В текущем архиве находятся README и docs.

## Как предложить изменение

1. Создать issue с описанием проблемы и ожидаемого результата.
2. Приложить минимальный пример с вымышленными данными, версией схемы, часовым поясом и точными временными границами.
3. Сделать изменение в отдельной ветке.
4. Добавить регрессионный сценарий, подтверждающий исправление.
5. Обновить документацию при изменении контракта или поведения.
6. Открыть pull request с причиной изменения, результатом, проверками и совместимостью.

Для ошибки свободных денег полезны отдельно: cash, необходимая выплата, текущий бюджетный резерв, будущие недели, покупки и кредитный резерв. Все эти значения в публичном воспроизведении должны быть синтетическими.

## Требования к изменениям расчётов

- Не смешивать факты, планы и уже обеспеченные суммы.
- Не вычитать одну выплату одновременно из cash и повторно из обязательств.
- Не заменять неизвестный горизонт или остаток фиктивным нулём.
- Сохранять идемпотентность сетевых повторов.
- Проверять влияние на историю, границы дней и зарплатные периоды.
- Изменение правил доступа не прятать внутри исправления арифметики.

## Защита содержимого репозитория

Публикуются структура, алгоритмы, тесты и синтетические примеры. Реальные операции, банковские графики владельца, дампы данных, ключи, идентификаторы рабочей базы, необезличенные логи и переписки остаются вне репозитория.
