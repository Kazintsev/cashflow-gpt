Опубликованы полные тела 76 функций, DDL 19 таблиц и 4 представлений, связи, индексы, последовательности, триггеры, начальные права, собранный bootstrap, синтетический набор и автоматические проверки. Документация содержит вводную часть, сценарии, API, инструкции агентам и машинные каталоги со ссылками на SQL.

Индивидуальные значения зарплаты, даты начала учёта и форматирования банка удалены из переносимого кода. Данные и права рабочей базы не копировались. [Состав и отличия](source-code.md).

Установка в пустую схему и 14 проверок прошли на PostgreSQL 18.3 через PGlite 0.5.8. [Что проверяется](testing.md) · [Первый запуск](start.md).

9 сентября 2026 года установка и демо также проверены на отдельном Supabase PostgreSQL 17.6. Все 12 групп [native-smoke](../tests/native-smoke.sql) прошли; повторная установка и повторная загрузка защищены от выполнения на заполненной базе. [Облачный отчёт](testing.md#supabase-validation).

## Что остаётся до полного открытого выпуска

| Работа | Критерий завершения |
|---|---|
| Подключить клиент | Настроены роль, авторизация, разрешённые и запрещённые операции; проверен реальный канал |
| Упаковать ИИ-интеграцию | Поставляется один воспроизводимый Actions / MCP / иной адаптер |
| Расширить покрытие | Проверены оставшиеся случаи матрицы, конкуренция, восстановление и временные границы |
| Подготовить обновления | Есть версионируемые миграции для уже установленной базы; bootstrap предназначен только для пустой схемы |
| Выбрать лицензию | Добавлен LICENSE с выбранными владельцем условиями распространения |
| Зафиксировать выпуск | Выбрана версия, проверены серверные команды и опубликованы изменения поведения |

Публичная видимость репозитория сама по себе не заменяет открытую лицензию. [Лицензирование репозитория на GitHub](https://docs.github.com/articles/licensing-a-repository)

Фактическая структура описана в [source-code.md](source-code.md#layout). Каталоги `integration/` и `supabase/migrations/` сейчас не поставляются. Поле `private: true` в package.json предотвращает публикацию технического пакета в npm и не задаёт видимость GitHub.

## Как предложить изменение

1. Создать issue с описанием проблемы и ожидаемого результата.
2. Приложить минимальный пример с вымышленными данными, версией схемы, часовым поясом и точными временными границами.
3. Сделать изменение в отдельной ветке.
4. Добавить регрессионный сценарий, подтверждающий исправление.
5. Обновить документацию при изменении контракта или поведения.
6. Открыть pull request с причиной изменения, результатом, проверками и совместимостью.

Для ошибки свободных денег полезны отдельно: cash, необходимая выплата, текущий бюджетный резерв, будущие недели, покупки и кредитный резерв. Все эти значения в публичном воспроизведении должны быть синтетическими.

## Требования к изменениям расчётов

- Не смешивать факты, планы и уже обеспеченные суммы.
- Не вычитать одну выплату одновременно из cash и повторно из обязательств.
- Не заменять неизвестный горизонт или остаток фиктивным нулём.
- Сохранять идемпотентность сетевых повторов.
- Проверять влияние на историю, границы дней и зарплатные периоды.
- Изменение правил доступа не прятать внутри исправления арифметики.
